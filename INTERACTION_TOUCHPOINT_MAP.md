# Interaction Touchpoint Map: ScriptureForge AI

## 1. User Personas (Actors)

Based on the core product vision and permission matrix, the system serves the following distinct personas:

1.  **Everyday Believer (`User`)**
    *   **Goal:** Read scripture, maintain personal journals, track prayer requests, and participate in Live Bible Study Rooms.
    *   **Primary Interfaces:** Web App (Consumer Views), Mobile App.
2.  **Small Group Leader (`Moderator`)**
    *   **Goal:** Manage group workspaces, generate study guides (AI), host and manage Live Rooms, track attendance.
    *   **Primary Interfaces:** Web App (Moderator Dashboards), Mobile App (Host Views).
3.  **Pastor / Teacher (`Author`)**
    *   **Goal:** Deep structural analysis, access lexicons, utilize AI for sermon-to-discipleship content pipelines, curriculum creation.
    *   **Primary Interfaces:** Web App (Advanced Research Layouts/Workspaces).
4.  **Church Administrator (`Tenant_Admin`)**
    *   **Goal:** Org-wide configuration, billing, member provisioning, doctrinal profile settings.
    *   **Primary Interfaces:** Web App (Admin Settings Panel).
5.  **System Administrator (`Super_Admin`)**
    *   **Goal:** Global platform diagnostics, infrastructure telemetry, security audit enforcement.
    *   **Primary Interfaces:** Backend CLI, APIs, Infrastructure Dashboards (Grafana/K8s/Terraform).
6.  **Machine Integrations (System Personas)**
    *   **Zoom Webhook Sender:** Submits real-time meeting events to the webhook ingress.
    *   **LLM Provider (OpenAI/Anthropic):** Interacts with the AI Context Assembly engine.

## 2. Interaction Boundaries & Touchpoints

### 2.1 Web Application (Next.js) `[GUI]`
*   **Authentication Flow:** Login, Registration, Password Reset, MFA setup (Cognitive friction risk point).
*   **Global Library / Reader View:** Scripture reading interface, translation comparison panels, accessibility modifiers (font sizing).
*   **AI Context Assembly / Study Plan Generation:** Prompt input interfaces, source citation views, doctrinal guardrail feedback UI.
*   **Live Bible Study Room Canvas:** Real-time video integration (Zoom embedded or linked), synchronized text focus, chat/interaction panels, prayer request boards.
*   **Workspace / Dashboard:** Sermon content uploading, micro-devotional output review, group management, attendance logs.
*   **Settings / Configuration:** Profile management, Tenant Administration panels.

### 2.2 Mobile Application (React Native) `[GUI]`
*   **Authentication Flow:** Login, biometric integration.
*   **Reader / Journaling:** Optimized scripture reading, offline/cache states, personal journal entry.
*   **Live Room Companion:** Real-time synchronization canvas (poll pattern fallback), chat, prayer requests.
*   **Notifications:** Push notifications for room starts, devotional reminders.

### 2.3 Backend Engine (Go / Rust gRPC) `[API / CLI]`
*   **REST API Layer (Go):**
    *   `POST /api/v1/auth/*`: Authentication endpoints (DX: Token handling, validation error schemas).
    *   `GET/POST /api/v1/rooms/*`: Room management and configuration (DX: JSON structure, state mutations).
    *   `POST /api/v1/webhooks/zoom`: Ingress for Zoom events (DX: Payload validation, HMAC signature errors).
*   **WebSocket Layer (Go):**
    *   `WSS /api/v1/rooms/stream/{room_id}`: Real-time event distribution (DX: Connection lifecycle, binary/JSON frame ergonomics).
*   **Scripture Engine (Rust gRPC):**
    *   Internal microservice communication for high-performance scripture retrieval and vector search (DX: Protobuf schema clarity).
*   **Infrastructure / DevOps (Terraform/CLI):**
    *   Provisioning commands, log aggregations, telemetry queries (DX: Command ergonomics, error clarity).
